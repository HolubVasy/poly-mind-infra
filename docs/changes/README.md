# Спеки больших изменений

Где что лежит:

- **Notion** - планы, ограничения, черновики идей и итоги после merge. Таблица «Изменения»: строка на изменение, «Принято ✅» только после живой проверки. Это журнал для людей, CI его не читает.
- **Git** - конкретные требования к фиче. Мелкая правка описывается в самом PR по шаблону. Для большой задачи рядом с кодом, в том же PR, кладётся спека: `docs/changes/<ГГГГ-ММ-ДД>-<тема>.md`.

Большая задача - та, где больше одного файла логики, есть платные вызовы, меняется деплой или то, что видит мама.

Claude review читает спеку, на которую ссылается PR. Пропущенное требование он считает багом: код делает не то, что обещано.

Шаблон ниже. Скопируй его в новый файл и заполни.

```markdown
# <Тема>

Строка в Notion «Изменения»: <ссылка или «нет»>

## Цель
Одна-две фразы: что станет лучше и для кого.

## Требования
Каждое проверяемо: по нему можно сказать «сделано» или «нет».
1. ...
2. ...

## Не делаем
Что сознательно остаётся за рамками, чтобы ревью не считало это пропуском.

## Как проверим
Какой тест, прогон или наблюдение подтвердит каждое требование.

## Риск и откат
Что может сломаться в чате и как вернуть.
```

# Ревью по общему процессу: проверки, перепроверка находок, роли

Строка в Notion «Изменения»: https://app.notion.com/p/6a9b0c7d8c004446bd7ab93ee5e0f422
Образец: страница Notion «Процесс: требования в git, ревью с Claude» (job-search, core-services-v4).

## Цель
Процесс в этой репе такой же, как на странице-образце: ревьюер видит результат проверок, каждая находка перепроверяется вторым запуском, а красный ставит только подтверждённый баг. Роли и границы автономии записаны в CLAUDE.md.

## Требования
1. На PR `Validate` запускается как job `checks` внутри `Claude review` (reusable workflow). Его однострочный итог попадает в промпт ревью, красная проверка - первая находка. На push в main `Validate` работает сам, как раньше.
2. Ревью ищет только баги и публикует находку только со сценарием поломки (состояние, file:line, что сломается). Итоговый комментарий начинается строкой `REVIEW <sha7>: N finding(s)`.
3. Если N > 0, второй запуск перечитывает находки того же коммита и публикует `VERIFIED <sha7>: C confirmed, P plausible, R rejected`. При N = 0 второго запуска нет.
4. Проверка красная, если: нет строки REVIEW для этого коммита; есть находки, но нет строки VERIFIED; C > 0. PLAUSIBLE и REJECTED не блокируют.
5. Круг - push после REVIEW с находками. После 3 кругов ревью больше не запускается, один раз пишется «Лимит ревью», последнее состояние сохраняется (красное остаётся красным).
6. Шаблон PR получает строку `Notion:`; шаблон спеки ссылается на строку в «Изменения».
7. CLAUDE.md: роли, красные линии, три корзины автономии, цепочка изменения, Notion как ручной журнал, определение круга.

## Не делаем
- Не подключаем Notion к CI и не даём ему токен.
- Не трогаем `image-smoke.yml`, `model-check.yml`, `deploy.yml`.
- Не делаем проверку обязательной в настройках GitHub: на бесплатном приватном плане это недоступно.

## Как проверим
- Этот PR ревьюится своей новой версией workflow: видно job `checks`, строку REVIEW и, если есть находки, VERIFIED.
- Тестовый PR с подложенным багом: находка -> VERIFIED с confirmed -> красный; исправление -> «0 findings» -> зелёный. PR закрывается без merge.
- Тестовый PR с ломающим validate.py изменением: `checks` красный, ревью называет его первой находкой.
